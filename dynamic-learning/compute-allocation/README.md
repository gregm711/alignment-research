# What does shared search buy on one harder induction problem?

## Iteration one, registered before evaluation

A machine applies a hidden length-d sequence of four named operations to a symbol, drawn from an alphabet of 67. A learner receives the primitive tables, program length and four distinct input/output demonstrations. It must produce exact outputs for 12 fresh input symbols. One instruction is then replaced without revealing its position; four new demonstrations contradict the old program and 12 distinct unseen inputs are graded again. An episode succeeds only if all 24 outputs are correct. The target is behavioral equivalence on new inputs. The family prior, length and primitive semantics are supplied; the hidden sequence is newly sampled every episode.

Test the architectural idea of sharing intermediate hypotheses in a bounded workspace. Compare independent random complete programs, deterministic depth-first search sharing a prefix on one demonstration and checking survivors on the others, and bidirectional program synthesis joining partial executions on two demonstrations then validating all remaining examples. All three may first try a one-instruction repair of their last successful program. Count unsuccessful branches and their table reads, build inverse tables online at charged cost, reserve the same budget for transfer predictions, and record actual process CPU joules and elapsed time. There are no external inference calls. Communication is in-process. Limit the intermediate join table to 256 prefix programs (four levels); report entries, with no equal-byte claim. Extra compute is spent on each fixed instance, never by giving easier test cases to a smaller budget.

Use depths 2, 4, 6, 8, per-phase table-read allowances 128, 512, 2048, 8192, and 24 paired worlds per depth. Freeze seed 120310 for random invertible lookup tables and 120819 for a second family of invertible affine transformations modulo 67. Include the ordinary direct algebraic solver on the latter; charge calibration and output arithmetic, measure joules for its actual code path. Correctness on held-out symbols is verified outside the meter; generation of the provided problem and test labels is common. All learner setup, interpretation of receipts, repairs and rendering returned outputs are inside the meter. Downstream checks here mean evaluating known receipts, not querying a world for new evidence.

Predict that at depth 8 bidirectional search attains 90% exact episode solves at a lower budget than either one-ended strategy on random tables, and that direct affine induction wins on the matched-accuracy energy curve for affine data. Both are established algorithms. This experiment calibrates the price of serial vs shared computation; a new neural architecture has not been tested. Report joules per exact solve (including failures), per-depth reliable reach at >=90% observed success, and paired uncertainty where relevant. Any learned allocation policy is a subsequent iteration.

## Iteration two, registered before running the controller

The first sweep found a composition law that bypassed search entirely. Test a recurrent controller that chooses whether to accept a compact candidate rule, probe it again, or expand to the full linear model. The unknown rule is a binary shift register with n hidden feedback coefficients. Predict its state after three and seven recurrent applications on eight new inputs, then repeat after the taps change. Widths 8, 16, 32 and 64 give up to 2^64 candidate rules per phase. The domain and candidate representations are supplied. Budget 8, 16, 32 or 72 device probes per phase. The learner receives one additional common nonzero-output observation per phase (on revision, one that contradicts the previous true rule). Each call transmits an n-bit stimulus and one feedback bit. No stored skill library or external model.

The first hypothesis is that a cheap one-tap proposal often explains either the initial rule or its change. Use binary index probes to propose a tap, challenge it with independently seeded random probes, then answer or fall back to basis queries if it fails. Reuse all earlier observations through incremental binary elimination. Compare exact basis identification, fixed policies with 0, 1, 2, 4 or 8 challenges (give the best fixed challenger in hindsight), and a tiny fitted policy that chooses that count per width and budget, trained on separate worlds. The rule and revision independently use a single random tap with probability 0.75 and otherwise a uniform nonzero mask. Reuse the exact questions from the fitted policy in an ordinary linear decoder. Count verification, failed attempts, transmitted bits, training and whole learner CPU energy. The finite active state grows with width and stays bounded per problem.

Freeze the fitted policy before running a second family in which a complex change has exactly three taps. Use independent seeds for train (170000), primary (270000), and transfer (370000). Use 48 test episodes per cell. Predict that the fitted policy beats basis identification below n probes, especially on the sparse component. Advancing a learned controller requires improving on the best fixed policy at matched accuracy and energy on transfer. Inspect gains and harmful early answers separately. An established feedback-register solver winning is a valid negative result.

Before scoring, specify the fitted policy and baseline unit. Fit separate challenge counts for initial learning and revision at each width and budget, using paired phase success then fewer probes as the training criterion, on 24 training worlds. Fit the revision count using the chosen first-phase policy. On each test cell compare against every fixed challenge count applied to both phases, and report the best single global fixed count as a deployable comparison. The decoder returns a consistent solution with free coefficients zero when underdetermined. The meter includes the simulated one-bit oracle and learner-side logging. Oracle records are never passed as solver parameters.

## Iteration three, registered after inspecting iteration two

Drop fitted verification counts as the leading design. Change only which input the first verification uses. The binary index questions for a sparse rule predict an input wire j. A one-hot input at j directly checks whether this purported wire contributes to the new rule. For a three-wire change involving distinct a, b and c, the proposed j = a XOR b XOR c cannot equal any of them. Hence one targeted check must reject a false single-wire proposal if the incumbent is correct. A dense change can contain j. More dangerously, a five-wire change can contain j and four other wires whose indices XOR to zero. The probe can then pass a false rule.

Compare one targeted vs one random challenge and targeted plus three random vs four random challenges at widths 16/32/64, budgets 8/16/32/72. Freeze 96 fresh worlds per width per distribution, with seed bases 470000 (one or three taps), 570000 (one or unrestricted), 670000 (one or five taps deliberately sharing the single-wire index signature). Compare on the same worlds, with a shared random suffix after the first check, and include basis and zero-check comparisons. Repetitions at larger allowances use the same worlds. Predict an improvement in exact solves or fewer probes at equal solves on the three-tap distribution, and a reversal on the constructed five-tap case for single-check policies. The primary comparison is width 64, cap 72, single check, exact episode solves and mean probe count. Report paired discordance and three batched energy readings for this comparison. Disclose that the proposed query uses the supplied parity structure. This tests choice of experiment, without attributing the policy to a trained network.

## Iteration four, registered before sourcing the external coefficient sets

The three-tap targeted check moved 91/96 to 96/96 at width 64 and 72 probes; the same change moved 86/96 to 75/96 on five-tap aliases. Test a representation that can accumulate more than one changed coefficient. Start from the last rule and cache all observed parity equations. If any observation contradicts the current mask, split that observation's active inputs in half, test one half and keep the half with odd residual. Repeat until one differing coefficient is identified and flip it. Exploit cached observations before asking again. Four fresh random confirmations permit an early answer. Compare always splitting, switching to exact basis completion after two flips, the preceding four-random-check candidate, and exact basis. Each consumes the same observations available to its own policy and may use the same oracle. This version is deterministic given the probe seed and has zero training cost.

Freeze the algorithm and seed before opening the external corpus. Use the published pycrc model catalogue to obtain all distinct generator polynomials at 8, 16, 32 and 64 bits where two or more exist. Treat coefficient masks as feedback rules in the same controlled shift-register task. Evaluate every ordered pair at each width, or a seeded uniform sample of 96 if larger, applying the same random wire permutation to both masks. These are externally specified coefficients in a simulated task, without any CRC table or model name available to the solver. Domain-aware dictionary lookup is consequently outside the stipulated input. Report underlying distinct polynomials, per-width solves and probes at several budgets, plus actual CPU joules. Episode labels within a width reuse polynomials. Include matched fresh one/three-tap and dense synthetic controls. Predict a multi-coefficient workspace improves exact solves at width 64/cap 32 against the four-check incumbent on one/three-tap rules. Expect exact basis to remain formidable at sufficient budget on external polynomials. Failure on those coefficients limits transfer claims. Keep further neural training contingent on identifying a decision the ordinary algorithm handles poorly.
