# Can a circuit learn which observations share a source?

Protocol recorded before scoring. One network of 32 persistent relays sees a sequence of independent fair binary events. In a fixed private group of 20, one common ancestor per event reports the event correctly with probability 0.62. Each relay flips its inherited report independently with probability 0.04. The other 12 relays independently see their own 0.62-reliable observations. An episode can purchase one new independent 0.80-reliable event reading. There are no visible source IDs. All policies observe the same eight unlabeled calibration events if they elect to use history, followed by 64 test events. In the drift condition the group is independently redrawn after 32 test events without notice. A frozen estimate and a rolling estimate compete with an ordinary vote, a simple known-group voter and a check-only policy. The known-group voter gets the current true membership for free as an oracle. The trainer sees separate worlds from the same generating family.

Estimate each relay's redundancy by counting nearby relays in the preceding eight-bit history within a learned Hamming radius, including itself. Weight the current reading by the reciprocal of this count and aggregate the votes. Fit the radius from 0, 1, or 2 and whether to request at margins below 0, 2 or 5 votes on training worlds. A trained check policy pays 0.1 correct answers per request when fitting, then scales the checked evidence by the known reliability log odds. No source labels or held-out feedback enter inference. Count the optional check and its evidence consistently in all policies.

For every decision the inferred bit selects the order of two privately held random permutations of 16 symbols. Each is invoked on the previous result. The tables and test input change on every event. The evaluator verifies the resulting symbol. Compare to a severed relay returning the second cell's lookup on the original input, using the exact same selected order and observations. Register an 8-point gain in end-task accuracy for rolling inference over ordinary voting on fixed topologies, above zero with a paired world-level 95% interval, and a 30-point loss under severing. Measure the cost in bits and inspections of sending all unlabeled history (no free provenance). Predict rolling recovers at least 3 points over frozen on events 9–32 after the swap. Train on 48 networks; evaluate fixed and drift on the same 128 fresh network seeds, with identical latent events and per-cell noise across policies within a condition. Use no tuning on test scores.

Use a prearranged fixed endpoint order: one report bit per relay per event; eight times 32 bits during calibration for policies that need it. Computing on these packets locally costs CPU time and energy. Every decision additionally routes two argument and two return packets; charge a one-bit module address and four-bit argument for each call and four return bits. Charge requests and their answers two bits total. Distinct active cells per event count participating relays, the receiver, two permutation cells and the optional external cell; charge calibration touches separately. Report transfer quality, measured CPU joules and time for repeated batched inference on pregenerated data, excluding setup of the test fixture. Vectorized execution on one laptop can expose simulator overhead; the network itself is logical.

Training uses 24 fixed and 24 drifting networks; the three competing vote-based arms also fit their check thresholds. Use paired bootstrap intervals over networks. Each energy record contains three timing blocks and the number of 8,192-decision inference batches per block. This includes calibration processing for history-aware methods and excludes synthetic generation, scoring and training. IDs and upstream truth stay private throughout history-based inference. The rank of the requested branch follows a deterministic tie-break.

### Can disagreement trigger a cheaper refresh?

After reading the periodic results, fix a gate before testing a new seed (60914, 256 worlds per condition). At setup estimate redundancy as before. Treat sensors within Hamming radius one of at least eight sensors including themselves as the suspected common group. Flag an event when their absolute mean sign is below 0.75; an empty group is also flagged. If two of the last four events were flagged, and at least six events have elapsed since the last refresh, recompute pairwise redundancy from the latest eight readings for those networks only, effective on the next decision. No state labels, drift notices or new types of evidence. Compare against continuous refreshing, a frozen map, and the fixed eight-event schedule, all with the same fitted check policy. Count setup and subsequent refreshes separately. Predict at least threefold lower process CPU energy than continuous refresh with a drift-accuracy deficit below 1.5 points on the fresh seed. The gate is an analyst-designed heuristic; its thresholds remain frozen even if it misses. Resource comparisons use the actual masked implementation. On the fixed worlds a frozen map is the cheap baseline to beat.

## Results

With hidden source identities and a fixed topology, refreshing estimates from the last eight unlabeled events solved 85.97% of two-operation queries. Ordinary voting solved 65.60%, the voter given true groups solved 87.10%, and purchasing an independent check every time solved 81.34%. Replaying the same independent checks to the ordinary voter preserved the 20.37-point advantage [19.32, 21.42]. Even with checks disabled for both, the gain was 14.84 points [13.79, 15.93]. Severing the intermediate argument cut the rolling learner to 6.38%. Across events 9–32 after a source swap, rolling inference beat freezing by 19.08 points [17.29, 20.90]. This method estimates redundancy from repeated joint observations and assumes stable relay identities between observations. Arbitrary hidden dependence on a first encounter remains unresolved.

Repeated correlation calculations have a price. On the second 128-world drift panel, computing them every eighth event used 1.74 µJ per decision versus 9.96 µJ for recomputing every event. Accuracy fell from 85.27% to 83.81%, a paired difference of −1.45 points [−1.99, −0.92]. On the original drift panel the deficit was 2.10 points. Periodic refresh therefore missed the specified 1.5-point target on the original panel; the fresh interval also includes losses above that margin. ### Refreshing on disagreement

On the separate 256-network drift panel, the gate recomputed its grouping an average 2.55 times after setup; the continuous learner did so 63 times. Both followed the same communication protocol and saw all sensor packets. Measured costs are per decision, amortized over batches. Logical bits and active-cell counts include calibration and optional checks.

| Drift policy | Exact answer | Bits | Active cells | Checks | CPU µJ | Wall µs |
|---|---:|---:|---:|---:|---:|---:|
| Freeze after calibration | 76.52% | 54.44 | 39.22 | .219 | .58 | .15 |
| Recompute every event | 85.06% | 54.72 | 39.36 | .362 | 10.24 | 2.57 |
| Recompute every eighth event | 83.70% | 54.67 | 39.33 | .333 | 1.76 | .44 |
| Recompute on disagreement | 83.81% | 54.69 | 39.34 | .344 | 1.79 | .51 |

The gate saved 5.7× in process CPU energy against continuous refreshing. Its 1.25-point accuracy deficit met the point prediction, with a paired interval for the deficit of 0.81–1.68 points. Against the periodic schedule the gain was 0.11 points [−0.28, 0.49], with slightly higher CPU energy on this run. On fixed topologies the frozen estimator reached 85.74% using 0.57 µJ versus 85.67% and 1.48 µJ for the gate. Frequent refresh buys accuracy when groups change. The additional logic of adaptive refreshing has yet to earn a clear advantage over the simple schedule.

The tests use synthetic near-copy channels, a known reliability model, two supplied operations and a single abrupt topology change. The check-only policy spends an external measurement on every event and needs no relay packets. The CPU meter excludes the energy of physical sensors and wires. The calibrated receiver uses quadratic pairwise comparisons on refresh, so the 32-relay result does not establish favorable large-network scaling. ### Audit of the corrupted-upstream claim

The previously reported 6.6% and 75.1% apply to a separate experiment supplying origin IDs. To measure the corresponding slice here, expose the planted ancestor's error only to the grader after inference. Reproduce the original fixed-world panel (19274, 128 worlds) and confirm on an unopened fixed-world panel (764582, 256 worlds). Report event-bit accuracy and end-task accuracy separately when the ancestor was wrong or right, for the rolling hidden-source estimator and an unweighted vote receiving exactly its check requests and answers. Repeat with no checks. Include overall scores because the error-only slice is selected by unavailable truth. Predict a positive accuracy difference in the wrong-ancestor slice and a penalty in the right-ancestor slice, estimated with a paired world bootstrap. This is a diagnostic on the synthetic generator.

On the new 256-world panel, 6,234 of 16,384 events had an incorrect shared ancestor. In that subset, event-bit accuracy was 0.0% for unweighted voting and 75.0% for hidden redundancy weighting with the same checks (paired gain 73.9–76.0 points, 95% interval). The estimator requested an independent reading on 53.4% of this slice. With no independent checks, the corresponding rates were 0.0% and 61.9%. On the 10,150 events with a correct ancestor, matched-check weighting fell from 100.0% to 92.0%. Overall, hidden weighting raised bit accuracy from 62.0% to 85.5% with identical receipts. The downstream permutation task sometimes maps either bit to the same answer; its wrong-ancestor accuracies were 6.6% vs 76.5% on this run. The windows contain the last eight observations per relay on every decision. These percentages describe the planted majority of near-copies and weak independent minority.
