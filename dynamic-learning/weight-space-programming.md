# When a foundation model writes another model’s weights

Research note, November 24, 2026.

## What the writer produces

A foundation model can describe a circuit by emitting numerical weights directly, or write a short program that fills the matrices. In both cases the small target can run after the writer is gone. Record which interface the writer received, whether it saw the task rules or only examples, which forward passes it could inspect, and how many submissions it made. These details change what a successful run establishes. Earlier work such as Tracr already translated formal programs into transformer weights. The recent capability is a general-purpose language model deciding how to realize the computation from a prompt. [Tracr implementation](https://github.com/google-deepmind/tracr) · [MIT experiments](https://rikiyat.github.io/blog/weight-space-programming/)

## What has been demonstrated

| Evidence | What the result buys us |
|---|---|
| **A working policy in one reply.** On MinAtar Breakout, an independent team obtained scores of 514, 550 and 307 from GPT-6 Astra against MIT’s 517. The writer had no tools. When the researchers flipped the board or exchanged the actions and supplied the changed game code, newly written networks also worked. | The writer can translate an understood policy into a network for a new specification. Two independent decompilations back into Python matched all 49,189 tested actions. On handwritten digits the written classifiers averaged 50%, below a simple 82% baseline. [Independent replication](https://arxiv.org/abs/2611.21449) |
| **A known algorithm in a loop.** In the November 23 MBZUAI report, Claude Opus 5.5 wrote matrix-construction code. Four attention heads let each maze cell read its neighbors. The repeated block propagates distances and traces a shortest path. The main 19,936-weight network and a 928-weight variant both scored 100% on the reported maze test. The group also reports Sudoku and a 20-disk Tower of Hanoi. | Parameter sharing lets one small circuit perform long computations. The writer could inspect development behavior, and recurrent steps still cost time. The quoted $19 covers the main maze construction session. Calling ordinary shortest-path code is an important baseline when the deliverable is simply a solved maze. [Methods, costs, prompts and limitations](https://mbzuai-oryx.github.io/LoopedWSP/) |
| **Editing an existing model.** MIT edited Qwen3.5-0.8B to suppress repetitive reasoning. A Claude replication substantially raised math scores by editing the output distribution, including the tendency to continue thinking. Separately, a 27B open model used graded practice answers and forward tests to edit itself, with a reported 6.6-point gain on held-out problems. | A change can persist in the weights. Decoding controls matter when an edit changes how often the model stops. These results concern particular failure modes and evaluation settings. [Original](https://rikiyat.github.io/blog/weight-space-programming/) · [Claude replication](https://arxiv.org/abs/2611.20953) · [Self-rewriting study](https://arxiv.org/abs/2611.21885) |
| **Installing a skill from task evidence.** WeightCode uses an LLM to generate a program that edits an existing target. Its evaluations include command composition, navigation and vision. Rerunning the editing program on independently trained vision models transferred substantially better than copying a fixed numerical edit. | The reusable discovery can be an algorithm for finding and editing the right place in a network. [WeightCode](https://arxiv.org/abs/2611.25476) |
| **Turning examples into a persistent update.** A November 23 revision evaluates four editors on six tasks. They often measure how demonstrations change the target’s hidden state, then install that change in the weights. Editors sometimes supply task examples from their own knowledge. Results weaken under strict example budgets and unfamiliar wording. | A strong comparison gives every method the same evidence and counts unfinished attempts. Include ordinary in-context learning and fine-tuning. The authors also already test sequential edits and replay. [Study, limitations and sequential experiments](https://arxiv.org/html/2611.26841v2) |
| **Inferring weights from observations alone.** A smaller exploratory study withheld the generating equations and asked for literal weights after showing a supervised dataset. Writers sometimes matched analytic solutions and sometimes missed a rule angled away from the visible coordinate axes. | Specify what information identifies the rule and test on new coordinate systems. Some impressive game results give the writer the simulator source, even on previously unpublished games. [Structured-data study](https://arxiv.org/abs/2611.19292) · [Private games and source access](https://arxiv.org/abs/2611.16981) |

Two adjacent approaches change the baseline. When writers could choose their own architecture on factual questions, they often built a searchable table. An explicit memory with the same evidence is therefore a serious competitor. A trained hypernetwork offers another design: Sakana’s Doc-to-LoRA processes a document once and emits a reusable adapter; its training cost is amortized across updates. [Architecture-choice study](https://arxiv.org/abs/2611.22055) · [Sakana’s Doc-to-LoRA and Text-to-LoRA](https://pub.sakana.ai/doc-to-lora/)

## The opening for this project

One result changes the experiment I would choose. In a sequential-edit run, an earlier antonym circuit remained intact while its accuracy went from 90.5% to zero. The next edit made inputs activate the country-capital behavior. Providing the writer with examples of the old task helped it repair interference. Both sequential editing and preserving a skill through replay already have direct prior art. [Sequential-edit analysis](https://arxiv.org/html/2611.26841v2)

**Proposed question:** can a small model with a writer-designed update mechanism figure out *which* rule needs revision from a stream of observations? Give the writer the task family once. Freeze its resulting circuit before drawing secret rules, arbitrary symbols and change points. Only the small model sees those episodes. If it succeeds, the writer has designed a learning procedure that works on fresh episodes without calling the foundation model for each change.

Start with an explicit rule table and a short Python learner under the same memory and observation budget. Include the case where two plausible rules make identical predictions until a decisive observation arrives. Score samples to recover after a change, retention of the untouched rule, inference work, and sensitivity to renaming symbols. Use the written circuit as a positive control for the trained sleep model. Because we know where the rule and its selector live in the written design, we can separately disturb each and test whether an internal monitor tells a lost rule from a rule the model can no longer access. This is a proposed experiment; priority over existing work remains unverified.

## Local artifact check — protocol

After a single hand-entered 5×5 maze to check output formatting, test the authors’ released default maze network on 12 reachable 7×7 boards. Prediction: it marks a shortest path on all 12. Use Python’s random seed 20261124, a wall border, and independent interior walls at probability 0.26. Draw two distinct open cells as endpoints, skipping disconnected pairs. Check the output against an independent breadth-first search. Require the original walls and endpoints, a connected marked path between the endpoints, and exactly the minimum number of marked cells. This is a CPU smoke test of the published weights. [Pinned release](https://github.com/mbzuai-oryx/LoopedWSP/tree/2752cd9f2d2e1e3e30e6686b3dbc23d8bcab875c/weights)

**Result.** All 12 boards passed. The independent shortest distances in draw order were 7, 3, 3, 2, 1, 6, 2, 3, 5, 4, 4 and 3 edges. This exercises the released default network on small inputs. The published Maze-Hard score, the 928-weight variant and the process that produced the weights were outside this check.
