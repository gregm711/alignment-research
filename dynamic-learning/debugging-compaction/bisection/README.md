# Can an agent revise a version bisection after a test worker is discredited?

A debugging agent has two more tests available to locate the first revision on which a reported bug is fixed. It has already collected results from two workers and formed a provisional diagnosis. A checkout audit then identifies the worker that tested the advertised commits and invalidates observations from the other worker. The agent chooses a search interval for its remaining two tests. The task measures a consequential debugging decision with executable outcomes and requires no code generation.

## An exact control for what information is missing

Test whether dropping worker identity can destroy information even for an optimal search policy. Use the six already measured release histories with first passing positions 3, 4, 5, 7, 8 and 9. Treat them as six equally likely anonymous release environments. Withhold the function name, commit hashes, timings and logs beyond the displayed binary measurements. Present the same four observations in the same order in every environment: revision 2 fails, 5 fails, 6 passes and 9 passes. The pooled diagnosis is revision 6 and is wrong in every environment. Reveal that red used shifted cached results and blue used the advertised checkouts. When the truth is below 6, blue supplied the measurements at 2 and 6. When it is above 6, blue supplied the measurements at 5 and 9. Red's reported results must be reproducible by consulting a shifted snapshot of the same real test. Independently verified endpoints 0 and 12 remain available.

Predict that an optimal policy without worker attribution can identify at most four of the six fixes with two binary checks, even if it knows the uniform distribution and all six possible positions. One bit identifying which pair of measurements came from blue should permit all six. Verify both claims by enumerating adaptive probes against the saved measurements and construct a single common anonymous input. This is a designed identifiability control. It does not estimate how often provenance is necessary in unselected debugging sessions, and the six environments are reused historical incidents.

## Results from the executable controls

All eight cases met the monotonicity and failure-signature criteria. The original public test ran once at each of 104 case/commit pairs. The bisection tool looks up those recorded outcomes for its chosen probes. Each arm pays the same logical two-test budget, and every run sees deterministic results. On every trajectory the last failure and first pass for the audited worker were enough for the tool to identify and independently certify the exact first passing revision in at most two midpoint checks. Pooling both workers' bounds gave the wrong revision in every injected-correction case and the right revision in every confirmation case. The ground-truth files contain the actual commit IDs and binary test outcomes. [Measurements](measurements.json)

In the six anonymous environments, the full source-blind report was identical. The best two-test decision tree could output at most four distinct answers, and enumeration found a tree achieving four. Knowing which two observations were attributable to the clean worker selected one of two four-revision intervals. Two additional measured outcomes then certified the correct revision in all six worlds. The single bit describes that particular binary assignment after the common log is given. A general handoff must encode the observed measurements as well. [Optimal tree, revisions served and independent certificates](identity-results.json)

Git already supports recording a bisection log, removing mistaken entries, and replaying it. Our constrained intervention asks what an agent can still do when only the compact handoff survives. In this setting a single worker's errors are correlated across requests. ## A shortcut in the first benchmark

Selecting the wider worker interval certified **all 16** original forks, including every correction. Selecting the narrower interval certified all eight confirmations and zero corrections. Picking one color always gave 8/8 confirmations and 4/8 corrections. Starting with the global endpoints gave 2/8 confirmations and 0/8 corrections. The broader interval always contains the real change and costs only two checks. Consequently, good scores on the eight original version histories can establish that a handoff helped a model choose a useful interval. They cannot establish that the model needed the identity disclosed by the audit.

Qwen certified 6/8 correction cases with the attributed table and 0/8 each with full logs, ordinary summaries, swapped labels, and its draft alone. Four of the six successes revised Qwen's own wrong initial guess. Only one of those four guesses had matched the wrong pooled diagnosis. All eight ordinary responses requested the global endpoints. Six full-log responses did the same. Qwen was discarding potentially useful measurements, often without committing to the earlier wrong answer. The full log missed its registered 5/8 feasibility threshold. On confirmations the five counts in order (full, ordinary, attributed, swapped, draft) were 4, 2, 8, 8 and 2. Ordinary, attributed and swapped notes used exactly 96 native tokens and the same total reader input size within each fork. [All Qwen choices, checks and certificates](qwen2.5-coder-7b.json)

## Matched reader test

Before collecting decisions, use the six anonymous worlds from the exact control above. The two possible worker intervals, (2,6] and (5,9], have equal widths. The logged revisions, outcomes and pooled candidate 6 are identical. Cross two assignments of interval to color with two possible identities for the audited worker. Each reader therefore makes four distinct post-audit decisions per arm. Each choice is replayed on the three compatible measured histories. Report distinct choices separately from the twelve replayed outcomes. For fixed assignment the initial input, generated provisional diagnosis and ordinary summary are shared across both possible audit results. No function names or true positions reach the model.

Compare the original chronological log, the ordinary model-written handoff, a deterministic two-row source table, the table with source labels exchanged, and a label-free table with both intervals in ascending position order. Match all four compact handoffs at 96 native tokens and verify server counts. For the label-free arm, the provisional guess is still the reader's own and can vary by color assignment. The exact information bound applies only to a fully source-blind policy. Record first guesses and whether they encode assignment information. Count choosing the correct interval on both audit results for each assignment, recovering from the reader's own wrong initial guess, and the resulting actual certificates. Predict at least three of four exact interval choices with the attributed table in each reader, at least two fewer when labels are exchanged, and at most two for a fixed label preference. The ordinary summary may already preserve both pairs. Report that tie if it occurs.

Qwen initially nominated revision 6 under both color assignments. That diagnosis was wrong in all six measured worlds. The attributed table produced the correct interval for all four distinct audits. The chronological log gave 0/4, ordinary 1/4, swapped 0/4 and anonymous 2/4. All four compact notes used the same total native reader input within a fork. Replaying the four attributed choices on their three compatible histories certified 12/12, compared with 2/12 for full, 3/12 for ordinary, 0/12 for swapped and 6/12 for anonymous. Both ordinary notes already contained all four individual outcomes with the correct worker names. Qwen benefited from having the candidate intervals computed and grouped by source before learning which one to use. The ordinary note's failure here cannot be attributed to losing those observations.
