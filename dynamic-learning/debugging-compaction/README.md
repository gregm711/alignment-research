# Can a compacted debugging session still change its diagnosis?

## Stage 1 — instrument development, before model trials

The proposed public result needs real debugging sessions, independent model families, and runnable patches. Begin with a cheaper test of the measurement itself. Eight small Python compatibility repairs reconstruct plausible incidents around documented library semantics. Two possible reference behaviors produce identical ordinary examples and disagree on edge cases. Captured calls to two reference implementations survive in the prefix. The working hypothesis favors one reference. A later routing observation confirms it or overturns it. Both branches receive exactly the same prefix, source code and pre-fork note. The model gets no later expected output. A freely authored replacement function must pass hidden discriminating and ordinary regression tests. These fixtures are authored mechanisms, not recordings of production incidents.

Use a local Qwen2.5-Coder 7B Instruct for the screen. Generate fresh greedy outputs in independent sessions, using exactly the same context window and output cap. Generate the compaction note before revealing either branch. Make the first comparison among full history, ordinary summary, evidence-preserving summary, and no earlier history. Both summary policies have a 96-token cap using the writer's tokenizer. Compare actual token counts as well as the cap. Test same-length evidence restoration and transcript retrieval after the first screen identifies an eligible failure. Keep every answer and failure. Validate the scorer with buggy and correct implementations for both endpoints and check the resulting branch labels before collecting predictions.

Prediction: full history will solve both branches in at least four of eight cases. Ordinary compaction will cost at least two overturn repairs that pass with full history. We expect preserving competing evidence to rescue at least one. A case gets no credit for an effect if its full-history patch fails. If suffix-only performs as well, the task provides weak evidence that old observations matter. A success here justifies more realistic traces. Never count output samples or branch variants as independent bugs. Use local compute, record model identifiers and inference timings, and keep downloaded weights outside Git.

## Stage 1 outcome and registered follow-up

Qwen solved both routes on 0/8 cases with the full history (prediction ≥4). Full history solved 3/8 confirmations and 1/8 reversals. Ordinary, evidence-instructed and empty handoffs each solved 2/8 confirmations and 0/8 reversals. All 64 candidates produced executable test outcomes. The sole reversal loss was deduplication. This fails the feasibility gate. These results do not establish a general compaction penalty. [Individual notes, candidate patches and test outputs](results/qwen2.5-coder-7b/).

## Repair-interface check and evidence readout, registered before these trials

The first historical Qwen reader gave a provisional score_text diagnosis after inspecting both a screen row and a fresh row. Its ten repair attempts all failed the expression interface. Nine used an unsupported top-level key, and the remaining expression attempted to replace final-answer candidates with intermediate-step booleans. Retain those attempts. Run one additional turn on each arm with the same original source, its own failed edit, the interface error, and JSON-constrained decoding for the two legal keys. No held-out test details enter the retry. This measures whether one ordinary edit-feedback cycle removes the interface failure. It cannot establish persistence of the original diagnosis by itself.

On the controlled cases, test whether the models can report the selected archive's observation without writing code. Show the saved note, fresh route and the first discriminating input. Ask which of the two frozen observed outputs the requested archive produced. Counterbalance answer order by case and repeat with reversed choices. Require a correct choice in both orders for credit. Compare full, ordinary, true record, label-swapped record and no handoff. Each branch gets the same answer options across memory arms. Predict at least 6/8 correctly read reversal observations with the true record for Qwen, even though its repairs failed on all eight. This is recognition of an observation, not evidence of successful coding. It separates attribution and output selection from writing a generalizing repair.

## Executable evidence, registered before the repair-with-feedback trials

A second engineer can preserve a small regression test at handoff. Test whether delivering a failed check changes the eventual patch even when merely archiving the same observed input and output was ineffective. In every arm, start from the stored ordinary-note patch for that reader, on all eight cases and both routes. Give one further repair turn. The original archive inputs and outputs are public to the agent. The evaluation inputs remain hidden.

The experimental memory is the frozen exact-length Qwen handoff from the restoration study. Once the route arrives, read its structured observation. In the run arm, execute the starting patch on that input and supply the observed value, expected value, and PASS/FAIL. In the unrun arm, give the same true input and expectation without the execution result. In the common arm, run the archived nondiscriminating input. In the swap arm, run the same discriminating input with the two sources misattributed. Every arm can revise the same initial patch once, even when the check passes. The selected test plus the current patch fit in a single repair prompt. Equalize total solver input tokens per case and route for Qwen using an explicitly labelled inert padding field. No hidden regression results go back to the model.

Predict at least two Qwen reversal fixes with the true executed check that the common check misses and at least one that seeing the same unexecuted expectation misses. Compare changes on already-correct patches too. Count a repair only if all hidden and shared regression examples pass. This exploratory second-turn test is on the same cases that motivated it. It tests feedback after a fixed starting patch; it is not a fresh end-to-end validation of the entire memory policy.
