# Can a router learn a new class from feedback it chooses to check?

## Protocol fixed before running

A text router accepts requests of one familiar intent A. It now receives the same contrary report in two possible worlds. In one, the queue must also handle previously unseen intent B. In the other its old policy still applies and the report was wrong. Intents C and D remain outside the queue. Queries are equally distributed across all four intents. The old classifier is imperfect and its mistakes are measured against the actual old policy. Unlike the handwritten-digit experiment there is no artificial mark that reveals the old answer. The new rule is a constructed queue expansion on naturally labeled text. [CLINC150 data](https://github.com/clinc/oos-eval) · [Earlier handwriting test](../handwriting-switch/README.md)

Use cached, frozen MiniLM vectors and all ten CLINC150 domains. Sort the domain names and use alternating domains for practice and evaluation. In each evaluation domain generate 128 seeded assignments of four distinct intents and their wordings. For each assignment fit the old router using 16 official training examples of each of A, C and D. It accepts A if its cosine similarity to the A prototype exceeds that to both negative prototypes. It sees no B wording. Choose a uniformly random B training example that the old model rejected for the opening positive report. Provide two menus of eight training requests sampled independently of their answers, two per class in random order. Score sixteen official test requests per class. The learner sees embeddings and old predictions, never the hidden class identities of menu or query items. Reserve distinct training wordings for every role, including verification.

Write a separate binary addition head with one positive gradient step on the opening and another step on each verified item. The deployed rule accepts a request if the old router accepts it or the addition head is released and accepts it. For fitting the addition, a positive verification on an already accepted request gives no evidence of an addition. Use online logistic updates, unit centered text features, a constant threshold and step size selected on practice domains. Compare a scalar step with per-coordinate positive learning rates estimated from same- versus different-intent request pairs in practice domains. These are alternative update directions with identical initial outputs. Compare random checks, the strongest predicted addition among old rejections, and choosing just by similarity to the original report among old rejections. Freeze settings before evaluation. When the whole menu is already accepted, use its first item. Compare two confirmations against one and always deploying the provisional classifier. A confirming check must verify a positive answer on a request the old router rejected.

The verifier itself has limited examples. On each assignment, give it two distinct reference texts per intent and use normalized nearest-centroid classification over the four intents, then map its predicted intent to the current policy. Its mistakes depend on wording. At the second check, compare reusing this verifier with using one trained on disjoint reference examples. Also compare an exact stochastic null with the same fraction of mislabels on each complete eight-item menu as the original verifier for that world. Redistribute the error probability uniformly among that menu's texts and independently across the two checks. Integrate all four paths. Include perfect verification. The null controls marginal error on the menu before selection. The observed error rates on chosen requests can consequently differ.

Primary comparison uses the scalar writer, two confirmations and the same text verifier. Require at least a three-point increase in changed-world query accuracy for predicted-addition selection over random, with positive lower paired bound, and an upper bound below two points for absolute harm to originally correct stable queries. Report accuracy on the new class B, repairs among initially wrong B queries, false flips, old-rule accuracy, verifier error before and after selection and release rates in both worlds. To support benefits from learning update directions require three points over the scalar writer with no more than two points excess harm. Report all domains and uncertainty using 2,048 paired episode resamples within each fixed domain. These intervals condition on five domains, a fixed encoder, and the available wording. No public-post claim follows from one benchmark.

For tuning, maximize equally weighted changed/stable accuracy of the two-confirmation, predicted-addition policy on 24 practice assignments per domain. Search step sizes 2, 6 and 16 and fixed negative intercept magnitudes 0.75, 1.5 and 3. Estimate the diagonal metric from 8,192 practice pairs by the ratio of different-intent to same-intent mean squared differences per coordinate with smoothing, clipping and unit mean. Center using practice training texts only. Report results relative to the frozen old classifier because high new-world accuracy can otherwise conceal a low B recall.

## Results

On 640 assignments across five held-out domains, selecting the largest predicted addition raised changed-world accuracy from 82.59% to 91.71% (+9.12 points, paired 95% interval +8.37 to +9.85). Recall on the newly added class rose from 35.75% to 78.89%. The old router already scored 82.10% overall on the changed policy. All five domains improved, by 6.98 to 10.85 points. Neither primary arm released a false addition in the unchanged world. A bootstrap over zero observed events gives a degenerate interval. A conservative one-sided 95% bound places harm among initially correct answers below 0.68% for independent draws from the five fixed domain populations. It bounds the chance of any harmed episode using the zero event count and the average eligible fraction using Hoeffding's inequality, allocating 2.5% error to each. The joint criterion passed on this task.

| Rule after the opening report | Changed-policy accuracy | New-class recall | Stable answers broken |
|---|---:|---:|---:|
| Two confirmations, random requests | 82.59% | 35.75% | 0 observed |
| Two confirmations, requests similar to the opening | 91.67% | 78.82% | 0 observed |
| Two confirmations, predicted additions | 91.71% | 78.89% | 0 observed |
| One confirmation, predicted additions | 93.12% | 85.47% | 0.13% |
| Always release after both checks, predicted additions | 93.27% | 86.08% | 0.46% |

Most of the gain was available by finding another request similar to the first. Updating the selector after the first check added 0.04 points versus that retrieval rule (−0.07 to +0.16). The practice-trained diagonal metric and scalar step tied to two decimal places. Both selected step six and intercept minus three. Even unconditional release after the two updates rarely caused harm here. The conservative two-confirmation requirement sacrificed 1.56 points of genuine-change accuracy compared with that control.

Errors from the text verifier were **less frequent** on the selected stable-world requests (0.78%) than across their full menus (2.89%). Redistributing the same menu-level error probabilities uniformly produced 0.11% harm. Using a verifier with fresh exemplars for the second check yielded 0.04%. Perfect verification also occasionally broke an initially correct prediction because a genuine correction to the imperfect old router can propagate incorrectly. These experiments model a verifier that knows the correct policy but can misclassify the intent. They leave open what happens when the verifier shares the learner's mistaken belief about policy itself.
