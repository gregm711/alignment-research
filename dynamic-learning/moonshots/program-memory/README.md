# Editing an executable rule after a scoped correction

## Protocol before scoring

A synthetic data-cleaning service has 16 clients in four groups of four. The public installed configuration has two distinct rules, each shared across two groups. A signed report names one client. Fork the same setup into four equally weighted worlds: false alarm, local correction, group correction, or correction for every client sharing the old rule. A corrected output can affect an already materialized pipeline result through either of two client transformations. Reporters describe a possible retroactive correction; historical caches ought to reflect the corrected semantics.

Each rule maps a four-bit input to a four-bit output. The common finite language has four instructions (rotate bits left one position, increment modulo 16, XOR with 3, or multiply by 3 modulo 16), composable up to length three. Deduplicate by the entire truth table. For each of 512 seeds from 2200000, choose two distinct installed behaviors expressible in at most two instructions. Choose the replacement uniformly among behaviors whose shortest program has exactly three. The learner knows the grammar and the installed configuration. It gets four verified randomly chosen inputs at each of three sites (reporter, another client in the same group, and a different group sharing the old rule). The site's inputs are shared across world forks. Select the maximum-agreement scope and program, breaking ties toward the narrower scope and then shortest/lexical program. Preserve each receipt explicitly. No hidden world label enters inference.

After serializing and restoring the learned correction, evaluate three representations of the identical inferred policy. An editable executable library can append a bytecode function and rebind only the clients selected by the evidence. A strong explicit rule table stores the inferred rule by its one-byte ordinal in the fixed small grammar, with identical bindings. A second explicit table stores its 16 outputs packed in eight bytes. Charge the same scope selector and reported site, the complete witness transcript, new rule, and persistent dependency index to each representation. Bit-pack two 4-bit values per witness row for input and output, plus one byte for site; encode the query count. Keep the installed configuration, grammar, immutable source records and original cache available to all. Evaluate an ablation which edits the shared function in place for any inferred correction, ignoring the local binding. Each rule baseline may use the same dependency-aware recomputation as the program. Also measure eager full recomputation.

Generate 128 existing cached outputs per seed. Each output applies an independently drawn first client followed by a second client to its input. Compare two repair schedules. Full repair recomputes all rows. Selective repair uses an index from client to dependent rows, then recomputes all rows which reference a rebound client, including second-stage dependencies. Charge actual serialized index bytes, separate cache reads and writes. Also evaluate a scan over immutable source metadata to select the same rows without a persistent index. Measure correctness on every fresh (client,input), historical cached outputs after materialization, exact represented policy, affected values missed, and previously correct values damaged. Truth-table checks across all inputs serve as a ceiling control that distinguishes lossy state from insufficient evidence.

Prediction: copying on write will improve local-world retention over the in-place ablation by at least five percentage points. Among methods with the same correct binding, expect identical accuracy for program and table. A program merits distinct architectural investment here only if it ties or wins on correctness and beats the compact ordinal baseline in persistent correction bytes or repair work. Report negative outcomes and averaged paired results across all world forks, with seed-level paired bootstrap intervals for the local retention contrast. Include per-incident traces and verify selective materialization against a completely fresh full recomputation. No neural generation, learned instruction vocabulary, unbounded search or energy claims in this pilot.

## Results

**Editing a four-line rule is cheap; knowing which callers should inherit the edit matters more here.** With only a local correction, editing the shared function in place preserved 56.72% of previously correct answers. Rebinding a private copy at the inferred scope preserved 100%. The gain was 43.28 percentage points (paired seed-bootstrap 95% interval 42.92–43.62). This is an intentionally unsafe aliasing ablation. A plain rule table also achieved 100% local retention.

| Stored update | Entire policy correct | All fresh values correct, averaged individually | Cached results correct after repair | Mean correction bytes including witnesses | Mean cached rows recomputed of 128 |
|---|---:|---:|---:|---:|---:|
| Scoped executable bytecode | 99.17% | 99.98% | 99.95% | 29.24 | 41.85 |
| Scoped rule ordinal | 99.17% | 99.98% | 99.95% | 27.75 | 41.85 |
| Scoped packed literal table | 99.17% | 99.98% | 99.95% | 33.00 | 41.85 |
| Edit shared function directly | 49.85% | 83.97% | 74.14% | 29.24 | 71.91 |

The scoped policies recovered the full intended function at every client in 2,031 of 2,048 incidents. In the other 17, the selected program was consistent with partial observations and differed on held-out inputs. Giving the inference routine all 16 input values at each of the three witness sites recovered every rule and scope on every seed. The program directly executed its restored instruction sequence on affected reads. In a second implementation, expanding the bytecode into a truth table up front gave identical per-incident results.

A witness transcript occupied 25 bytes. Site and scope added two, even on a false report. The update body held zero to three bytecode bytes, one ordinal byte on an edit, or eight packed output bytes on an edit. The 85 legal source strings expressed only 77 distinct functions. This tiny fixed language favors an enumerated ordinal, and all three methods had its interpreter available during inference. The budget excludes fixed implementation code, the original ledger, the common inference workspace and the time spent enumerating candidates. It measures serialized state, with no wall-clock or electrical efficiency assumption.

Indexed repair required a further **264.15 bytes** of persistent client-to-row dependencies on average, bringing the scoped program to 293.40 bytes total. It checked an average of 41.85 original cached outputs and issued 38.59 changes. Scanning source metadata on an edit gave exactly the same repaired rows with zero persistent index bytes, at a cost of 96 metadata rows scanned per incident averaged across the four worlds. Eager recomputation evaluated all 128 pipeline outputs. These are logical reads and writes, not physical device I/O. Both stages were checked for dependencies.

**Decision.** The program missed the distinct-advantage gate. Its benefit over an eight-byte literal table was real, and a one-byte ordinary rule identifier did even better. A stronger test would withhold compositions during design, charge for discovering and retaining a reusable subroutine, and allow the explicit baseline to intern and reuse its own rules. The present task demonstrates neither open-ended program discovery nor automatic protection from collateral edits.

Run `OPENBLAS_NUM_THREADS=1 python3 study.py` in this directory with NumPy installed. The script checks serialization, exhaustive-evidence identification, and agreement among indexed, scanned and full recomputation on every fork. A separate rescore checked the fork counts, encoded update sizes, and exact-policy rates in the saved records.
