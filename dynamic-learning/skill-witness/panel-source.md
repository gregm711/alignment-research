# External episode construction

Each producer gets one eight-operation bank for its entire history. On the first available release the initializer buys ten formatter outputs. It fits one date or phone transform to those ten examples using the frozen grammar in `ops.py`. When exact induction fails, it chooses the public candidate with the lowest error on those same examples. Every arm receives the same initialized bank and incurs the same ten calls once per producer. This setup tests updating beliefs about programs that are already available. Invention of additional operations after calibration would require another experiment.

The other seven slots are chosen from deterministic edits of the first program and public formatting primitives. Date edits change separation, field order, zero padding, year length or numeral system. Phone edits change separation, prefix, grouping or digit removal, including edits inside a previously induced conditional rule. Each family sorts by error on the paid support. Families then take turns filling slots. Behaviors with identical outputs on every public input, including undefined outputs, share one slot. Completely undefined programs are discarded. The ordering, eight-slot limit and public candidate catalog are fixed in `panel.py`. Different producers can have different programs at the same index.

Input assignment hashes sorted canonical input fields with BLAKE2b keyed by the public constant `skill-witness-public-v1`. It takes the first ten public input values for queries in every revision. The remaining values form the grading pool after excluding any value that appears in any producer's query pool in that corpus. Inputs and fixture membership are public and used for alias elimination. Only the ten selected first-release labels influence the bank. In later releases a learner can see the outputs of paid queries. The driver controls access to grading labels. Missing releases are skipped. The release index in the API is the zero-based index in the upstream chronology.

The bank is shared, read-only model context. Its storage, ten-call setup and candidate execution are separate costs from the private recurrent state. A useful headroom diagnostic is the maximum held-out accuracy achievable by choosing one program after seeing the grading labels. Also record the fraction of releases any single candidate solves perfectly. A pointwise oracle allowed to choose a different program per example has a higher ceiling but can overstate the headroom of a single-program selector. Conversely a policy that votes over candidates may exceed the best single program. Identical predictions on the available checks with distinct grading predictions flag ambiguities no choice of check within this pool can resolve. All oracle calculations are retrospective diagnostics.

The finite catalog and annual sampling restrict the types of change this panel can detect. Shared formatters, locales and software releases also limit the number of independent observations. The fixtures measure exact software behavior on these input grids. Wall energy and broad architecture performance require separate measurements.

Run `python3 dynamic-learning/skill-witness/check_panel.py` from the repository root. This constructs both fixture types in a temporary directory and changes every future gold label and every unpurchased calibration label. The candidate programs, prediction matrices and input assignments must stay identical. It also checks cross-producer query/grade disjointness, slot count, causal release filtering and a synthetic calibration with a known solution.
