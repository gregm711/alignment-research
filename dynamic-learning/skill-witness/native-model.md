# Training the writable state and its probe policy

## Registration before fitting

Use eight persistent float16 logits (16 bytes) as the full private state. A new revision applies a learned uniform drift rate. Within a revision, a returned observation selects the smaller of the matching and nonmatching hypothesis groups. A shared learned update network changes at most four slots, with the direction given by the match bit. The query policy scores the equality partitions induced by possible checks. Inputs are summaries of how each check splits current probability and how much those splits overlap distinctions made by other available check inputs. The learner never receives a hidden test row or its result. Program identifiers affect its behavior only through past state and equality of proposed outputs.

Generate synthetic revision streams over eight hypotheses, initially uniform and redrawn uniformly with probability 0.22 per transition. Each new revision has its own distribution of output partitions. Six observable checks and separate future decision inputs are independently drawn from the same local distribution. Returned labels occasionally come from another hypothesis. Train through the recurrent state updates using expected held-out output log loss after choosing a probe. Evaluate a frozen model on 384 fresh streams, clustered by stream, at zero, one, and two checks. Repeat with writes suppressed, with the query policy given a uniform state but the same adaptive answer reader, and with a hand-written Bayes update and a maximum-entropy check. The oracle reliability and drift parameters for this synthetic world are available to the hand-written control. Two-check held-out accuracy should improve by at least five percentage points over disabled writes, with a positive paired lower 95% bound. A distinct learned probe benefit requires one point over the uniform-query-state intervention and over Bayesian entropy selection with positive paired intervals. Sterile, permuted, and all-match feedback and a restarted state must satisfy mechanical invariants. Results on external date and telephone inputs are separate, and hidden outcomes from those panels are never used for training. Report model size, precision and timing separately from dynamic state.

## Synthetic results

With 384 independently generated four-revision streams the trained state reached 70.69%, 88.20% and 93.70% held-out output accuracy at zero, one and two checks. Disabling every write produced 53.59% at all budgets. Replacing only the state used to choose checks with a uniform state reduced accuracy at two checks by 3.78 percentage points (paired stream-bootstrap 95% interval 2.73–4.90); this changes evidence acquisition across the whole lifetime. A known-noise, known-drift Bayesian reader using maximum-entropy checks reached 93.82%. The learned model's difference from it was −0.12 points (−0.59 to 0.33). The five-point write criterion passed. The joint one-point learned-check advantage failed.

The trained uniform drift probability was 0.229 (data generator 0.22). Routing each observation to at most four slots is hard-coded; backpropagation learned the magnitudes of the sparse writes, shrinkage at revision boundaries, and the scoring of probe partitions. The shared parameters occupy 268 bytes (67 float32 values) in addition to sixteen bytes of persistent float16 state per learner. Program pools, executable candidate signatures and transient inference buffers are external to this accounting. Training sampled 5,760 streams in 180 optimizer steps, using 3.8 process CPU seconds here. The counterfactual training cost includes probabilities for the outcomes of all six checks, under one independently drawn noisy answer per available check in each revision. Each chosen check spends one observed example during deployment. Its training-time competitors' labels are unavailable at inference. Exact parameter and score arrays reproduced in an isolated second run with CPU Torch 2.1.0.dev20230517 and NumPy 1.24.4. ## Follow-up registered after the original synthetic scores

A learner deprived of all writes also loses its within-revision response to new examples. To specifically quantify durable memory, replay only the retained-state model's two real checks on each of three later revisions in 384 fresh streams (seed 912571). Hold every query and returned answer fixed. Replace the state carried into each revision with either an empty state or the retained state of the next independent stream cyclically. Use the same trained readout and update rule throughout. Report held-out accuracy separately for true unchanged and actually changed hypothesis identities. Predict positive paired aggregate retained-minus-reset accuracy before the first check and smaller magnitude after two checks; expect negative pre-check differences on actual changes. No model or hyperparameter changes.

## Matched-observation replay results

Across 1,152 later revisions, carrying the right sixteen bytes into a revision improved zero-check accuracy from 54.54% to 76.01% versus reset. The paired 95% stream-bootstrap interval for the 21.47-point difference was 18.71–24.10. On exactly the same two observations, the remaining benefit was 2.83 points (1.89–3.78). Transplanting the next independent learner's private state gave 46.74% and 90.35% accuracy at zero and two checks, respectively.

The 240 revisions where the rule actually changed tell the other half of the story. Starting from the previous state reduced accuracy from 55.99% to 43.12% before the first check, a 12.86-point penalty (8.02–17.92). After observing the same two checks, the penalty was 0.78 points, with an interval spanning zero. On the 912 stable revisions, carrying memory helped by 30.51 points before any check and by 3.78 points after two. One state's usefulness therefore depends on how often the environment really changes and what further observations cost. This experiment uses the synthetic generator and candidate identities.
