# Can a bounded neural learner recognize when a familiar formatter has changed?

## Registered before inspecting either historical collection's behavior

A learner serves successive releases of a black-box formatter. Measure whether it remembers a producer's convention, buys a useful check and corrects an output when that convention changes. All policies may see the producer ID, current inputs and release boundary. The underlying package is the evaluator. If the deployed version is known and callable at negligible cost, calling it directly solves this problem. We study emulation when verified calls are the scarce resource.

Two source collectors chose 30 Moment locales and 30 phonenumbers regions before inspecting any changes. Each captures actual versioned outputs on a fixed grid of public or generated inputs; exact upstream versions, selectors and provenance are in the source notes. Each producer's earliest available version supplies ten paid introductory checks. Separate, permanently withheld input values are used only by the grader across all releases. Warm states compete across the entire stream of producers. Policies cannot read saved outputs or diagnostics to recover their earlier state. Producers run in a fixed outcome-independent order in each release. The collections are independent implementations, with repeated conventions within each.

**Primary architecture**: one fixed fast-weight tensor shared by all 30 producers in each collection. A sparse local update changes an addressed part of the tensor, from which the decoder produces output characters directly. Current inputs may be copied or reformatted; no bank of past programs, example archive, or producer-indexed growing state is available to this learner. The shared copy/literal vocabulary is its inductive bias. Train a small query policy on independently generated formatting episodes to predict the value of the next verified observation. Score it with its weights frozen and a writable state that persists across releases. Compare with the same decoder and fixed query order, frozen writes after introduction, and a larger fixed capacity. Timeouts, failure to write unfamiliar outputs and out-of-vocabulary characters count against the learner. Count exact rows, whole revisions with all rows correct, and verified calls for caps of 1, 2 and 3 checks on each subsequent revision. Stop when the current prediction passes the chosen check; otherwise update and continue to the cap. Report false acceptance whenever the final passing check or checks hide any incorrect withheld prediction. Report newly broken rows among previously correct unchanged rows. Include setup checks in cumulative cost and report whether a saving breaks even at comparable accuracy. An unlimited explicit library is not a candidate architecture.

**Controls**: an ordinary scoped synthesizer that stores the prior formatter and its prior failing check for each producer, and a practical repair baseline with retrieved previous formatter, most recent failing example, local off-the-shelf Qwen code generation and ordinary synthesis. Compare on identical inputs and budgets, with the more capable baseline free to retain state. If a mismatch triggers fresh synthesis, only currently purchased outputs may validate a repair. The codegen control may keep the incumbent when it remains more accurate on those observations. At the primary cap of two, test whether at least 20% of total verified calls are saved against each practical control, success is noninferior within two points, and the upper paired bound on excess regression is below two points in both panels. Require a lower paired bound above zero on call savings. Report paired bootstrap intervals clustered by producer, noting cross-producer interference. Treat sparse natural changes as insufficient for general revision claims. Running a cheap rule store or codegen with more memory is permitted and its memory must be reported separately. Separately test the learned query mechanism with swapped or uninformative selection at fixed readout, under a matched receipt replay or the same verified budget where practical.

**Secondary diagnostic**: a separately trained controller with a small writable state over a fixed eight-hypothesis bank. Measure full-bank representability and compare it to a classical likelihood update on the same hypotheses and observations. This is diagnostic routing over provided operations and its bank is an extra resource. Its results cannot establish that the primary decoder has learned a new operation. Artifact files, raw outputs and checkpoints exist only for reproducibility. Every run is local; the only external fetches are public releases. The original 3/38 spreadsheet result establishes a ceiling for one particular supplied grammar, not that learned primitive invention is necessary.

Implementation choices fixed before opening historical scores: the primary eight-cell decoder hashes producer IDs and writes three feature rows within one cell. The 32-cell control changes capacity alone. The query policy is ridge regression over uncertainty and public input shape, trained on 128 seeded, simulated formatter episodes. Its target rewards improvement on eight independent examples and detecting a mismatch when any of those examples is wrong. The swapped control rotates query scores by three positions. Producers run in lexical order within release. Grade immediately after the producer's update. Report the two-check comparison first; the one- and three-check comparisons show sensitivity. Prior observations used purely to score newly broken rows are inaccessible to every policy. No hardware energy meter is available for this study.
