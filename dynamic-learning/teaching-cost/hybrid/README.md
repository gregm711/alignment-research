# How should a learner divide 4,128 writable bytes?

## Protocol before scoring

Continue the open-weight teaching-cost study on the same two generators and 96 fresh lifetimes per domain (seeds 1210000 and 1310000 onward). Preserve the frozen policies, original encoder cache, 96 practice tools, eight new tools per lifetime, common six teacher observations, and 90% threshold. Compare the original 32-entry quantized neighbor and four float64 decoder-row updates to a hybrid of 16 quantized neighbors (2,064 bytes) plus the four output updates stored at float32 (2,064 bytes). Average their field probabilities equally without tuning or new parameters. Also score each hybrid half alone. Make identical history and evidence available to all. The primary prediction requires the hybrid to need at least 0.10 fewer new examples than *each* full-size parent on both domains, with paired lifetime-bootstrap 95% intervals above zero. Report bits per truthful observation and verification accuracy after one wrong answer as secondary outcomes. Raw arrays have axes lifetime, target, method, condition, step. The comparison measures persistent numeric payload; measuring lookup and model execution cost is separate. A win suggests complementary information under this cap, with external transfer still open.

## Outcome

On numeric tools, the hybrid needed **3.107 examples** versus 3.233 for 32 episodes and 3.199 for full-precision weight updates. The paired savings were 0.126 (95% interval 0.065–0.193) and 0.092 (0.039–0.147). On text tools it needed **3.225** versus 3.276 and 3.228 respectively. Its 0.003-example advantage over the weight-only parent had an interval from −0.048 to 0.051. Retaining weights at float32 alone reproduced the full-precision teaching counts in both cohorts. The 16-episode arm alone needed 3.309 and 3.473 examples. The hybrid's added arithmetic includes both a similarity lookup and a four-row weight read; matching writable bytes leaves those execution costs different.

The registered joint 0.10-example target failed. Splitting memory offers a measurable numeric benefit, and the text result gives little reason to install a fixed 50/50 mixture everywhere. These are new independently sampled lifetimes within the original two task generators. Run `OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 python3 compare.py`.
