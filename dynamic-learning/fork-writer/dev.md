# Fork-writer development fixtures

Registered before model evaluation or byte-budget scoring. Use 24 development episodes with seed 4701 and 48 fresh development episodes with seed 4702, split evenly between CLINC utterances and Moment.js historical formatting observations. Each ledger contains eight named witnesses and identifies the currently active one. The uncompressed ledger is common to all three questions. A later clue names one of two different other witnesses; which two will be queried is unavailable to the writer. Give the two forks the same two semantic alternatives, independently balancing and randomizing the order of options in each question. Balance the four joint fork-answer patterns within each domain to the extent the panel size permits. Present asks about the active witness. Mutually distinct underlying answers are required for the two futures even on episodes whose answer letters coincide. Source names, row order, content assignment and option order are randomized independently of their semantic role.

A CLINC witness supplies an authentic request. The choices are fresh utterances from two intents, and the label is the option sharing its intent with the chosen witness, using the published annotation. A date witness supplies one historical, locale-specific output on a known input; the options are real outputs on a fresh date. Exclude pairs of formatters giving the same string on either date used for that episode. These are constructed fork tasks on familiar development data.

Try fixed byte caps in multiples of eight, choosing the largest cap whose median ratio to raw UTF-8 history length is within 10–25% in each domain and where an ordinary suffix drops at least one future witness on at least half of episodes in each domain. If domain lengths have no common feasible cap, report the incompatibility instead of choosing a cap on replication. Whole UTF-8 bytes count, with an incomplete leading codepoint dropped on a suffix. Compare a deterministic verbatim writer that saves the active row first (then shortest complete rows, without seeing questions), charging every retained byte. Record the observed coverage of the needed complete source rows. Coverage is an oracle evidence-availability diagnostic. Answering questions from the retained content still costs inference and can fail. A stronger structured ceiling assigns each witnessed intent or observed format a code using the generator's known catalog. The latter has privileged semantic labels for CLINC. No confirmation data are used.

The rule selected **56 bytes** on the 24 screening histories, a median 13.7% of CLINC history length and 22.4% of date history length. On the 48 new development episodes the corresponding medians were 13.2% and 23.1%. A verbatim suffix at this cap retained both needed future rows on 0/24 and 1/48 episodes. The active-first, shortest-verbatim-row writer retained the active row on 23/24 and 46/48, and retained both future rows on 0/24 and 0/48. A model can still guess from the two options when a row is missing. Each panel balances the gold letter for all three questions within each domain.

A shared public-catalog reader reconstructs every answer on both seeds with **8 bytes per episode**. It maps each named source's utterance to its annotated CLINC intent or each date witness to the set of compatible archived locales. The order of the eight names is fixed across episodes. There are 150 possible intent codes and only 13 distinct sets of matching locales. The later clue names the source and the later options each correspond to catalog entries. This comparator has access to CLINC annotations for the exact development utterances, the archived per-locale outputs and the generator format. Its parameters and source lookup table are additional fixed resources. This verifies uniqueness of all 216 gold decisions under the catalog and shows that raw truncation alone does not establish an informative compression bottleneck. These fixtures can select a model capable of reading evidence. Beating verbatim truncation here cannot establish learned semantic compression or an advantage over structured evidence retention.

From the repository root run `python3 dynamic-learning/fork-writer/dev.py`. Both shared local data files are verified against their existing SHA-256 pins. To regenerate missing input caches see [CLINC data preparation](../intent-learning/prepare.py) and the [Moment.js source collector](../skill-witness/dates-source.md). No model requests or confirmation examples are part of these checks.
