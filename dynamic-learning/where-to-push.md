# Which changes should a learning model keep?

Research assessment, November 24, 2026. The rankings are judgments about the next experiment. The numerical results below belong to the cited studies.

## Revised priority — can experience improve the model's next weight update?

We subsequently ran [two CPU experiments and a weight-intervention check](plasticity/README.md). The learned update rule specialized to the practiced features and missed the predefined capability target.

The broader capability question is whether a model's hundredth unfamiliar task takes fewer examples to learn because of what changed in its weights over the preceding 99. The alignment question is whether those same changes make it more prone to absorbing a rewarded mistake. Both questions concern the *trajectory* of the learner. The scope-of-correction project below is one possible diagnostic along that trajectory.

The brain-inspired idea is **metaplasticity**. Prior activity can change how readily later activity strengthens or weakens a connection. Kirkwood and colleagues demonstrated experience-dependent changes in the induction of plasticity in rat visual cortex. Artificial versions have substantial prior art, including neuromodulated networks, context-gated continual learning, and metaplastic binary networks. Recent work also tracks how changes in a language model's readout affect its ability to learn from subsequent updates. Biological plausibility gives us a hypothesis. These engineering precedents set the bar for a contribution. [Rat visual cortex](https://pubmed.ncbi.nlm.nih.gov/8632826/) · [Backpropamine](https://arxiv.org/abs/2002.10585) · [ANML](https://arxiv.org/abs/2002.09571) · [Synaptic metaplasticity in binarized neural networks](https://www.nature.com/articles/s41467-021-22768-y) · [LM learning dynamics](https://arxiv.org/abs/2609.33620)

**Proposed experiment.** A small transformer learns a sequence of unfamiliar tools with executable specifications. Tools share underlying operations, while their names, argument conventions and compositions change. Some feedback reports actual execution. A second signal reports user approval, which sometimes rewards a plausible wrong answer. On held-out tools, measure two curves after successive checkpoints: executions needed to reach a fixed accuracy, and the rate at which the model endorses the wrong result when the user favors it. Compare the latter under matched tool competence, include correct as well as mistaken user suggestions, and track whether rejecting bad advice also makes the model ignore good advice. This measures a particular form of truthfulness under social pressure. [Sycophancy and preference feedback](https://arxiv.org/abs/2310.13548)

Start with a conventional adapter updated using Adam and a frozen model given examples in context. Then add one small, persistent gate controlling how strongly each group of adapter weights responds to the same proposed update. For the capability comparison give the systems identical experience, restart with a fresh context for each evaluation, and then supply the same new demonstrations. Include unseen compositions and unrelated tool families, so faster learning can be distinguished from recognizing familiar tasks. Record starting accuracy as well as the full learning curve. Compare a fixed gate, a tuned learning rate, and Adam with its ordinary optimizer history. Match or report extra parameters, stored state, computation and total training experience, including training the gate.

**Test the mechanism.** Save the adapter weights, gate state and optimizer state separately at successive checkpoints. Fork one checkpoint and hold its adapter weights, next examples, and optimizer state fixed. Give one fork the experienced gate and the other its initial or shuffled state. Before learning, both forks should make identical predictions, since the gate acts only on updates. Give both the exact same first gradient and test their subsequent behavior. Repeat on many forks. If the experienced gate speeds learning while increasing susceptibility to bad feedback, that trade-off is itself worth explaining. If a tuned scalar or Adam reproduces both curves, the added machinery has yet to earn its cost. A follow-up can vary recurrent depth or offline replay one at a time.

**Role for a foundation model.** Let it propose a compact, inspectable gate or its update rule on development streams. Freeze the proposal, disconnect the writer and evaluate the child on secret streams. Compare with a hand-written rule, a gradient-trained gate and an equally budgeted search over simple update rules. Record whether the writer produced numerical weights or code. Existing work already demonstrates direct weight construction and statistical inference on new data. Superior lifetime learning, or an explainable capability–truthfulness trade-off, would be the additional result. [Independent weight-writing replication](https://arxiv.org/abs/2611.21449) · [Programmed statistical inference](https://arxiv.org/abs/2611.20174)

## Earlier proposal — how broadly should a correction apply?

The same surprising observation can mean a sensor was wrong, one machine changed, or every machine of that type now works differently. Each interpretation calls for a different weight update. We know which future decisions ought to change, and we can test whether the weight change itself makes them change. The rankings below reflect the earlier scope-focused assessment.

## Where the evidence changed my mind

| Research thread | What the primary studies establish | Consequence for us |
|---|---|---|
| Looped transformers | Huginn spends more computation per token by repeating a shared block. A 3.5B-parameter model improved on reasoning benchmarks as depth increased. Yang et al. found that small looped transformers could match standard transformers on several in-context data-fitting tasks with under a tenth of the parameters. A constructed looped transformer can even execute a learning algorithm specified by its input. [Huginn](https://arxiv.org/abs/2502.05171) · [Yang et al.](https://arxiv.org/abs/2311.12424) · [Giannou et al.](https://proceedings.mlr.press/v202/giannou23a.html) | Give recurrence a job we can measure. Can a second pass over yesterday's observations change what the model learns from today's correction? Count the cost of every pass. |
| Sleep and test-time training | In the November sleep paper, four passes over completed windows matched the no-sleep model's held-out code loss with about 2.39× fewer prefix tokens, at higher training compute. The experience lives in the KV cache. The earlier sleep paper writes fast weights before clearing the cache. TTT-E2E goes further toward ordinary training by predicting the next token and updating transformer weights on the incoming context. [November paper, Fig. 2 and local reading notes](README.md#starting-point--learning-during-sleep) · [Fast-weight sleep](https://arxiv.org/abs/2605.26099) · [TTT-E2E](https://arxiv.org/abs/2512.23675) | Specify what survives a restart. Compare replay with spending the same compute on a gradient update or at query time. Prefix-length savings and total compute savings are different quantities. |
| A foundation model writing weights | An independent Breakout replication produced effective networks, and decompiled the policy into ordinary code. On digit classification the written networks averaged 50% against an 82% simple baseline. More consequentially, GPT-6 Astra programmed nanoTabPFN from zero weights and reached mean ROC AUC 0.849 across 20 tabular datasets against 0.876 for the pretrained baseline. That target already performs inference on new datasets. [Breakout and digits](https://arxiv.org/abs/2611.21449) · [Weights & Caches](https://arxiv.org/abs/2611.20174) | A learner written by an LLM is already credible. A stronger question concerns a new update rule, how it works and the conditions under which someone would use it. |
| What the writer actually produces | WeightCode reports that rerunning an edit program on independently trained vision models preserved much more benefit than copying the original numerical edit. In a separate six-task study, editors often wrote the effect of examples on hidden activations into the weights. Changes in prompt wording degraded results. SEAL generates the data and instructions for a gradient update, a third interface. Self-modifying matrices trained by ordinary meta-learning also predate this wave. [WeightCode](https://arxiv.org/abs/2611.25476) · [Writing in-context learning into weights](https://arxiv.org/abs/2611.26841) · [SEAL](https://arxiv.org/abs/2506.10943) · [Self-referential weight matrices](https://proceedings.mlr.press/v162/irie22b.html) | Record whether the writer supplies literal parameters, a program that constructs them, or a training recipe. For a reusable learning rule, freeze that artifact before revealing any test stream and account for failed writer attempts. |
| Human learning and replay | In human motor experiments, Heald and colleagues found evidence for a model in which people infer which context produced an observation. A behavioral change can come from expressing an existing memory or updating one. Human rest studies found replay of weakly learned items and sequences organized by inferred relationships. These results suggest experimentally separable hypotheses about when and what to replay. [Motor learning and the COIN model](https://pmc.ncbi.nlm.nih.gov/articles/PMC8809113/) · [Schapiro et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC6156217/) · [Liu et al.](https://pubmed.ncbi.nlm.nih.gov/31280961/) | The brain analogy earns its place if it predicts different behavior from a simpler rule. Compare replaying the most surprising observation, the weakest memory, and an older observation that distinguishes two live explanations. Human behavioral and imaging data do not identify the weight update a transformer should use. |
| Editing and continual learning | MOCA infers unannounced task boundaries. SERAC explicitly models an edit's scope with retrieval. WISE edits a side memory and routes queries between memories. MQuAKE found editors that could recite a corrected fact yet missed consequences that followed from it. Task arithmetic already transfers some behaviors by adding or subtracting parameter differences. [MOCA](https://proceedings.neurips.cc/paper/2020/hash/cc3f5463bc4d26bc38eadc8bcffbc654-Abstract.html) · [SERAC](https://proceedings.mlr.press/v162/mitchell22a.html) · [WISE](https://arxiv.org/abs/2405.14768) · [MQuAKE](https://arxiv.org/abs/2305.14795) · [Task arithmetic](https://arxiv.org/abs/2212.04089) | Detecting a change, routing an exception, transferring a weight difference and measuring collateral damage all have prior art. The opportunity is to identify *which* scope ambiguous evidence warrants, then causally test that scope in a continuing learner. |
| Alignment and interpretability | Narrow fine-tuning can alter behavior far outside the training domain, including with a rank-one adapter. CUPID already tests which earlier user preferences apply to a new request. Jin and Ren forecast individual examples that a weight update will break and use those forecasts to select replay data. A recent model-diffing study reports isolating causal directions across ten fine-tuned model organisms. [Emergent misalignment](https://arxiv.org/abs/2502.17424) · [Rank-one result](https://arxiv.org/abs/2506.11613) · [CUPID](https://arxiv.org/abs/2508.01674) · [Forecasting forgetting](https://proceedings.mlr.press/v235/jin24d.html) · [Delta-Crosscoder](https://arxiv.org/abs/2603.04426) | A small update can have broad behavioral effects. A monitor should predict a specific unwanted effect on unseen examples and beat cheap behavioral checks at the same audit budget. A toy rule correction can test this mechanism. Claims about assistant alignment need a separate behavioral evaluation. |

## 1. Best first paper — how far should one correction generalize?

Imagine a fleet of label printers. One prints the date backward. Three worlds have the same history up to this point. The event was a one-off misprint, this printer received a firmware update, or every printer of this model received it. A good learner should be uncertain now. A later diagnostic batch distinguishes the worlds. Tomorrow's jobs include fresh dates on the same printer, a previously unseen printer of the same model, and a different model. Those queries distinguish memorizing an exception, learning a local rule, and learning a shared rule. An independent rule, such as how quantities print, provides a control on the very same jobs.

**The first experiment.** Fork an identical learner checkpoint and identical observations into those three futures. Balance the causes. Check programmatically that their likelihoods agree before the diagnostic batch and that the batch distinguishes them. Counterbalance the wording, printer identities, order and symbol mappings. Hide whole combinations and a second task family from development. Test before and after the diagnostic evidence. Score uncertainty on the ambiguous prefix, then score where the rule should apply, where the old rule should survive, and on a two-step consequence that never appeared in the examples.

Give a small learner a writable parameter matrix and fixed temporary memory. Compare a gradient-updated adapter, a learned update rule with and without offline replay, and a simple detector that routes among stored rules. Give a retrieval system the same storage allowance, including keys and metadata, and report a full-history reference and a Bayesian reference with access to the generator. Match observations, count update and query compute separately, and show an accuracy–storage curve. A handwritten solution with access to the rules is a reference for what is possible. A tuned, compact routing heuristic with the same evidence is a serious competitor.

**The decisive intervention.** Cold-start from the shared base checkpoint with only the saved parameter change from one branch. Clear the transcript, cache, recurrent state, replay buffer and optimizer state. Test on fresh jobs. Then transplant the proposed component into a sibling with a different, independently learned quantity rule. Does the date correction follow it, with the right scope, while the sibling's quantity rule survives? Compare with transplanting the whole update, a norm- and rank-matched random component, and one from an unrelated correction. Restoring the entire update demonstrates persistence. The partial transplant tests what the update controls. Use siblings with the same weight coordinates so that permutation differences do not muddy the first result.

**My proposed decision rule.** On held-out worlds, advance the architecture if it improves post-correction accuracy by at least five percentage points over the strongest development-selected practical baseline, with a paired 95% interval excluding zero, and the upper uncertainty bound on excess errors outside the correction's scope is at most two points. Group by independent world and show variation across training seeds. Those are proposed thresholds for spending more time, not measured effects. Replicate the direction on a second domain, such as document-format or user-workflow preferences, before making a broader claim. Give that domain its own in-scope and out-of-scope labels. If simple routing ties, it becomes the candidate to explain and stress-test. A synthetic win alone supports a controlled research note.

**Why us.** Our forked-memory experiment already separates information a memory retained from information the model could use. Our Inkling intervention redirected lookup to the donor's token position in 109 of 115 eligible prompt pairs. Those precedents make a causal experiment feasible. Neither establishes a persistent, transferable correction. [Forked-memory evidence and its untrained control](forked-memory/NOTE.md) · [Inkling results](../jlens-inkling/SUMMARY.md)

## 2. Best narrower alignment paper — catch an overbroad update before accepting it

Give two updates the same immediate success on the corrected examples. One correctly learns a user's document preference for a single workflow. The other silently applies it to every workflow. Allow an auditor a fixed small number of *development* probes and ask it to predict which held-out workflow will break. An auditor that can advise rejecting or narrowing the second edit has a measurable use. The question applies equally to a hand-authored adapter and a learned one.

The comparison that matters is whether looking inside adds value over the correction text, the chosen probe answers, output probabilities and a gradient-based interference estimate. Evaluate detection at a fixed false-alarm rate, held-out by update and task family. Jin and Ren already forecast forgetting, and CUPID already measures contextual preference following. The proposed increment is paired edits with equivalent immediate behavior, an independently labeled boundary for appropriate generalization, and a fixed audit cost. Our grounding study found that adding the question type to confidence brought a cheap baseline within 0.03 AUC of an internal monitor. I'd treat another tie as a reason to publish the simpler audit if it travels to real edits. [Forecasting prior art](https://proceedings.mlr.press/v235/jin24d.html) · [CUPID](https://arxiv.org/abs/2508.01674) · [Our grounding comparison](../grounding/NOTE.md)

## 3. Highest upside, lowest odds — ask a foundation model to invent a useful learning rule

Give the writer a tiny recurrent architecture, a writable matrix, a memory limit, and several example task families. Let it submit one final set of weights or constructor. Disconnect the writer. The small model then encounters a secret stream with novel symbols, changing rules, noisy observations and recurring contexts. Measure examples needed to adapt, recover an old rule and withstand false corrections. Compare with a handwritten Bayesian learner, gradient descent, a conventional meta-trained fast-weight model, and the writer's best ordinary program at the same memory allowance. Report writer search cost separately from the child's lifetime cost.

I'd call this a strong result if an independently reproducible rule improves on the practical baselines across held-out families, and an ablation and a readable implementation explain where the gain comes from. If it rediscovers a known delta rule, that is a capability result about the writer. If the advantage disappears against the writer's plain program, the evidence favors algorithm synthesis and says little about the value of encoding it as a network. WeightCode's transfer tests and the nanoTabPFN result make this a higher bar than writing a maze solver. [WeightCode](https://arxiv.org/abs/2611.25476) · [Programmed statistical inference](https://arxiv.org/abs/2611.20174) · [Prior self-modifying learners](https://proceedings.mlr.press/v162/irie22b.html)

## What I would publish first

For an immediate public write-up, the best-developed material here is the **grounding audit**. It gives other researchers a check they can apply to their own benchmarks, and it documents a cheap baseline that changed our interpretation. For the next original research effort, I would fund direction 1 first. Direction 2 can use the same paired checkpoints. Direction 3 makes sense once the evaluation can distinguish a genuinely better learner from a clever implementation of a known rule. I would defer another search for the best time to sleep. In both of our timing pilots, we failed to establish enough benefit from an extra pass to justify optimizing its placement. [Grounding audit](../grounding/NOTE.md) · [Sleep-timing pilots](README.md)

Karpathy's autoresearch supplies a useful development workflow: fixed resource budgets, one editable experiment and a logged score. Here the score should reward correct transfer and penalize spillover, with a sealed final evaluation. Repeated selection on the same worlds can optimize the benchmark instead of the learning rule. I would borrow the workflow only after freezing those splits. [Karpathy's repository](https://github.com/karpathy/autoresearch)

The literature supports the feasibility of these ingredients. The open scientific claim is that inferring scope and selectively consolidating it buys something over retrieval, routing and ordinary fine-tuning under the same resource limits. Publication prospects depend on that comparison, independent replication, and how well the result survives a change of domain.
